# EgressView Agent for macOS

ルーターからは分からない「Mac上のどのアプリが外部へ接続したか」を確認するためのAgentです。取得するのはアドレス、ポート、プロセス名などの通信メタデータだけです。**通信内容を読み取らず、復号せず、通信を遮断しません。**

HostアプリとNetwork ExtensionはmacOSのApp Sandbox内で動作します。HostにはHub送信と署名済み更新確認に必要な外向き通信だけを許可し、Extensionには一般的な外向き・受信ネットワーク権限を与えません。両者が共有するのはEgressView専用のApp Group領域だけで、ホームディレクトリやAWS CLIのファイルを読む例外権限は付けていません。

## 必要な環境

**必須はひとつだけです。**

| 必要なもの | 理由 |
|---|---|
| **macOS 13以降** | ネットワーク監視に使うSystem Extension |

**Hubは不要です。** Agent単体で動かせば、このMacの外向き通信を監視し、**どのアプリケーションが**行ったかを示し、図にして、記録はこのMacに残ります。Hubへの送信は、あなたが有効にするまで行われません。

所要は5分ほどで、その大半はmacOSの承認操作です。

### Hubがある場合に増えること

以下はすべて任意です。**1台のMacを見るだけなら、この節は読み飛ばして構いません。**

| したいこと | 必要なもの |
|---|---|
| このMacの観測結果を、ルーターの観測と並べて1つの記録にする | **あなたが管理するHub 1.9.0以降。** **Hub 1.8.0以前はこのAgentを受け付けられません** — agent用のエンドポイントがありません |
| 脅威情報をHubから受け取る | **Hub 1.10.0以降。** 無い場合は「脅威なし」ではなく、その旨を表示します |
| そもそもこのMacを登録する | **そのHubの設定を操作できること。** 登録はMac自身ではなく、管理者の承認で完了します |

**Hubが無くても脅威情報は使えます。** 同じ公開リストを直接ダウンロードする単体用の設定があります。既定では無効で、下の「[このMacから出ていくもの、出ていくとき](#このmacから出ていくもの出ていくとき)」に、フィード提供者が何を知ることになるかまで書いてあります。

## インストール

1. [dl.egressview.com](https://dl.egressview.com/)から`egressview-agent-<version>.pkg`を取得します。
2. インストーラを開いて進めます。**アプリケーション**へ配置され、そのまま起動します。Agentはメニューバーに常駐し、専用のウィンドウを持ちません。
3. **ネットワーク監視**を選び、macOSのSystem Extensionを承認します。正式Sandbox版では、監視方式を迷わず選べるよう軽量監視を表示しません。

**インストールはここまでです。** この時点でAgentはこのMacの外向き通信を記録し、ここに保存しています。メニューからウィンドウを開けば見られます。

### Hubがある場合の接続

このMacの観測結果をネットワーク全体と並べたい場合だけです。**ここまでで何もMacから出ていません。**以下を完了するまで、何も出ていきません。

4. Hubの設定で6文字の登録コードを発行します。
5. Agentの**設定 > Hub**へHubのアドレスと登録コードを入力し、Hub側で申請を承認します。

Hubへの送信は既定で無効です。送信先と送信項目を確認して有効にするまで、このMacから観測結果を送信しません。AgentからHubへ接続する方式であり、HubからMacをポーリングしません。

インストール後の更新はAgent自身が行います。新しいバージョンを提示し、インストーラの実行まで引き受けます。**System Extensionの承認は再度求められません。**

## このMacから出ていくもの、出ていくとき

3つだけです。信じてもらうのではなく、確かめられるように一覧にします。

| | 送信先 | 内容 |
|---|---|---|
| **観測結果** | あなたのHub | アドレス、ポート、プロセス名。**ホスト名は含みません** — アプリが要求した名前はこのMacに残ります |
| **更新確認** | 署名付き配布サーバ | Agentのバージョン。初回起動時に明示します |
| **脅威情報と位置情報** | あなたのHub | **通信に関する情報を一切含みません。**一覧を丸ごと受け取り、照合はこのMacで行います |

**接続先を問い合わせのために外部へ送ることはありません。**これは設定ではなく、設計上の制約です。

### 自分で有効にできるものが2つ。どちらも既定で無効

Hubが無い場合、Agentは位置情報も脅威情報も持ちません。そのため自分で取得する選択肢を用意していますが、**設定で有効にするまで動きません。**

- **位置情報の取得**は、宛先IPアドレスを`ip-api.com`へ送信します。**Agentが監視対象のアドレスを外部へ送る唯一の経路**であり、だからこそ既定で無効です。
- **脅威情報の取得**は、`abuse.ch`と`spamhaus.org`から公開ブロックリストをダウンロードします。問い合わせサービスではなく単なるダウンロードなので、**あなたのアドレスは1件も送信されません。**相手に伝わるのは「このMacが取得した」という事実だけです。ダウンロードするのはこのMac自身なので、設定の横に各サイトの利用条件へのリンクを置いています。**同意するのはあなたです。**

**Hubがある場合、スタンドアローン用の設定は表示しません。**Hubが両方を供給しており、経路を二重に持つと「このMacから何も出ていかない」が静かに嘘になります。

**HubがダメでもAgentが勝手に公開フィードへ切り替わることはありません。**Hubが1時間落ちたからといって、あなたが何も触っていないのに送信内容が変わってはいけません。取得元を決める規則は「登録済みか」と「有効にしたか」だけを受け取り、**Hubが応答したかどうかを受け取りません。**これは主張ではなく実測しました——**Hubを3分35秒停止**してAgentを再起動し、取得を実際に失敗させた状態で、**第三者への接続は0件**でした。

### Hubが長く落ちたままなら、あなたの判断で代替を許可できます

数週間前の脅威情報では役に立たないため、長期の停止に対する逃げ道を用意しています。**有効にしない限り動かず、事故で発動しにくい**ようにしてあります。

- **必ずHubを先に試します。**毎回です。
- 自動取得が動くのは、保存済みの指標が**24時間以上古い**ときだけです。短い停止では手元のものを使い、どこにも接続しません。
- **「今回だけ公開フィードから取得」**のボタンもあります。いますぐ欲しいときだけ、1回。
- 設定画面に**現在の取得元**（Hub／保存済みキャッシュ／公開フィード）を表示します。どれを使っているかは常に見えます。

スタンドアローンの設定と同じく、**あなたの宛先は1件も送信されません。**相手に伝わるのは「このMacが接続した」という事実だけです。

### 取得できなかったリストがあれば、画面が名前を挙げます

脅威情報を有効にして件数が出ることと、守られていることは同じではありません。4つのリストを取得しており、**サイトが落ちている・形式が変わったなどで読めなかったものがあれば、設定画面がその名前を挙げます。**

> 指標 22,329 件。ただし threatfox, urlhaus は取得できませんでした。通信先は残りの指標とだけ照合しています。

これは逆のことが起きたために作りました。**2026年8月まで、4つのうち3つが無言で0件を返し続け、画面は合計値だけを表示していました。**本来の4分の1の指標で照合しながら、「照合した」と表示していたことになります。**静かなリストと壊れたリストが同じに見えてはいけません。**

Feodo Trackerはこの警告の対象外です。2026年3月から空のリストを公開し続けており、これは故障ではなく事実です。**消えない警告は、誰も読まなくなります。**

## 画面の読み方

- **ネットワーク状況** — 地球儀、流れの図、時系列、そして**その期間のどれだけを実際に監視できていたか**。
- **脅威** — フィードに載っている通信先と、そこへ到達したアプリケーション。**何も照合していないときはそう表示します。**照合していないのに「見つかりませんでした」とは絶対に表示しません。
- **通信ログ** — 期間内の全接続。列ごとに並べ替え・絞り込みができ、CSVへ書き出せます。

**監視開始前から確立している接続は観測できません。**Macがスリープしていた期間は、欠落ではなくスリープとして表示します。**画面は「分からないこと」を分からないと言います。**

地球儀は、このMacがこれまでに到達した国も記録します。**初めての国が初めてだと分かります。**

### 地球儀の更新頻度は選べます

毎秒3・5・15フレームから選べ、既定は5です。毎秒6度の回転に15フレームは要らず、差は電池に出ます。**ウィンドウを閉じているとき、別のタブを見ているときは完全に停止します。**誰にも見えない地球儀を回す必要はありません。

## 異常を知らせる通知

Agentから通知を出せます。種類ごとに個別のスイッチがあります——フィードに載っている通信先、監視の停止、Hubへの送信失敗、脅威情報の変化、復旧。**テスト通知**もあるので、**何かが壊れるのを待たずに経路を確認できます。**

通知が「無視することを学習される雑音」にならないよう、2つの制限があります。

- **同じ事象は1時間に1回まで。**繰り返し同じことを言いません。
- **1日の上限**（5／12／25／無制限、既定は12）。

**ただし監視の警告は、この上限の対象外です。**「記録されていません」は**このAgentが存在する理由そのもの**であり、脅威通知が多い日に押し出されてはいけません。1時間のクールダウンは同じく適用されます。

### 警報を鳴らして確かめる

**最も重要な通知ほど、動くところを確かめにくい**という問題があります。正直に再現するには収集を止めて30分待つ必要があり、それは**警報が守ろうとしている記録そのものを失う**ことです。そこで、直接発火させられます。

```sh
defaults write ~/Library/Containers/com.egressview.agent.macos/Data/Library/Preferences/com.egressview.agent.macos \
  diagnosticsForceNotRecording -bool YES
```

次回の健全性チェックがこれを拾って警告を表示し、**同時にフラグを消します。**一度だけ鳴り、**立てっぱなしにできません。**

**収集には一切影響しません。**このリハーサルは「止まっていないのに止まったと言わせる」ものなので、**警告する側にだけ倒れ、安心させる側には倒れません。**

この仕組みがあるのは、**警報が一度も鳴らないまま出荷された**ことがあるからです。

## アンインストール

先にアプリをゴミ箱へ入れないでください。EgressView Agentの**設定 > アンインストール**を開き、削除対象を確認して実行します。

1. Hubへの送信を停止し、Hub上のこのMacの登録を失効します。
2. ネットワークフィルタ設定とSystem Extensionを削除します。
3. ログイン項目、Hub資格情報、送信待ちキューを削除します。
4. 選択した場合だけローカル通信履歴を削除します。
5. Finderでアプリを表示するので、Agentを終了してゴミ箱へ移動します。

ローカル履歴は既定で残します。Hubがすでに受理したデータはHubから削除しません。Hubへ接続できない場合は資格情報を保持して再試行できます。ローカル処理だけを続ける場合は、HubのAgent設定から手動で登録を失効してください。System Extensionの削除にはmacOSの承認や再起動が必要になる場合があります。

## 開発者向け情報

ビルド、署名、公証、実装の詳細は[英語README](README.md)を参照してください。

**自分でビルドしたAgentも、更新確認は`dl.egressview.com`へ行きます。**この宛先はコンパイル時に埋め込まれており、**設定では変えられません。**変えるには`AgentUpdateChecker.defaultOrigin`を編集して再ビルドします。

**設定で変えられないのは意図的です。**更新の取得先を設定で差し替えられるということは、**別のバイナリを掴まされる経路を設定で作れる**ということです。このAgentは自分自身の外向き通信を監視するので、**どこへ問い合わせるかはソースを読めば誰でも確認できる**必要があります。

自分の配布ホストを立てること自体は想定内で、配布用のCDKスタックはドメインをcontextで受け取ります。
