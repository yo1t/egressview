# EgressView Agent for macOS が何を、どこへ送るか

> [English / 英語](agent-privacy.md)

エージェントはあなたのMacの外向き通信を見張ります。**その役目のツールは、自分自身の外向き通信について具体的でなければなりません。**「信用してください」は、利用者が確かめられる答えではないからです。

このページは、**エージェントが接続するすべてのホスト、その理由、そのとき端末から出ていくもの**を列挙します。アプリ本体とシステム拡張の両方に同梱している `PrivacyInfo.xcprivacy` マニフェストの、散文版です。

## 要点

- **観測結果はあなたのハードウェアに留まります。** 接続メタデータは、Mac上のapp groupコンテナ内のストアに書かれます。
- **開発者は一切受け取りません。** 分析エンドポイントも、クラッシュレポータも、いかなるテレメトリもありません。
- **ペイロードは読みません。** システム拡張はすべてのフローをそのまま通すcontent filterです。**誰がどこへ接続したかを記録し、何を話したかは記録しません。**
- **Hubに登録した場合、観測結果はそのHubへ行きます。それはあなたのHubです。** あなたが運用し、開発者はアクセスできません。

マニフェストの `NSPrivacyCollectedDataTypes` が「短いリスト」ではなく**空の配列**である理由がこれです。Appleは「収集」を、開発者または第三者がアクセスできる形で端末外へ送信することと定義しています。その定義に照らして、エージェントは何も収集していません。

## エージェントが行う外向き通信のすべて

| ホスト | いつ | 送るもの | 返るもの |
|---|---|---|---|
| **あなたのHub**（入力したアドレス） | 登録後、かつ送信が有効なときのみ | このMacのホスト名と、観測した接続メタデータ（ローカル／リモートアドレスとポート、プロトコル、プロセス名とID、取得できた場合のbundle ID、時刻、バイト数、収集方式と確度）。**ペイロード、認証情報、コマンドライン、ファイルパス、ブラウザURL、宛先ホスト名は決して送りません** | 受領応答、脅威フィードデータ、既に観測済みのアドレスの地図上の位置 |
| **`dl.egressview.com`** | 定期的な更新チェックと、「更新を確認」を押したとき | 通常のHTTPS GET。識別子もアカウントも観測データも含みません | リリースのmanifest、インストールを選んだ場合は `.pkg` |
| **`feodotracker.abuse.ch` / `threatfox.abuse.ch` / `urlhaus.abuse.ch` / `www.spamhaus.org`** | **フィードの直接ダウンロードを有効にした場合のみ**（Hubがフィードを供給するときは無効） | 公開リスト全体を取得する通常のHTTPS GET。**あなたの観測結果は送りません** — 照合はダウンロードしたリストに対してMac上で行います | 公開されている指標リスト |

4つ目のカテゴリはありません。**この表に無い場所へエージェントが接続しているのを見たら、それは報告に値する不具合です。**

### この表が隠せない1点

`dl.egressview.com` への接続は、任意のWebサイトを訪れるのと同じように、あなたのIPアドレスをそのホストのCDNに知らせ、CloudFrontはアクセスログを書きます。**これはHTTPSリクエストを行うこと自体の性質であり、エージェントが上乗せしているものではありません。** ここに書いているのは、都合の良い事実しか書かないプライバシーページは読む価値がないからです。

そのリクエストには、リクエスト自体を超えてあなたを特定するものは含まれません。インストールIDもアカウントも観測データも付いていません。

## 宛先の名前を読むこと、そして唯一復号するもの

**既定では無効**で、有効にしてもこのMacから出ていくものは変わりません。取り出した名前は**ここに残り**、Hubへホスト名が送られることはありません。

TLSでは、クライアントは鍵を合意する前に、行き先を平文で告げます。それを読むのに復号は不要です。

**QUICではそのメッセージは暗号化されており、これは復号します。** そうでないと書けば嘘になりますし、**この設定が信頼に値するかどうかは、その一点にかかっています。**

可能な理由は、QUICの**Initial**パケットの鍵が、平文で流れる接続IDから、RFC 9001に公開された手順で導けるからです。**ネットワークを見ている誰にでもできることです。** 観測者から守られていたものは、何も明らかになりません。

届くのは**最初のメッセージ**だけです。以降のパケットはTLSハンドシェイクから導かれた鍵で守られており、観測者はそれを持ちません。**Agentは QUIC の会話を読めませんし、今後も読めるようにはなりません。**

ブラウザのClientHelloは1つのInitialパケットに収まらないことが多く、**2つに分かれて届きます**。そのため最初のメッセージが揃うまで読み、揃った時点で終わります（2026-08-24に実測: 27フローで callback 56回、うち28回が2つ目のパケット）。**読む範囲は「最初のメッセージ」のままで、広がってはいません。**

### 読めた名前が、行き先とは限りません

**ECH（Encrypted Client Hello）**を使う接続では、平文で告げられる名前が**多数のサイトが共有する公開名**です（例: `cloudflare-ech.com`）。本当の宛先はその内側で暗号化されており、**読めません——ネットワークを見ている誰にとっても読めません。**

**そしてAgentは、ある名前が公開名かどうかを判定できません。** ChromeはECHを使わない接続にも同じ拡張を送る（GREASE）ため、**観測者から見て本物のECHとGREASEは区別できません。それがECHの設計目的です。** 判定できないものに印を付ければ、正しい名前の大多数に誤った印を付けることになります。

実測ではまれです（このMacで、名前のある観測521,575件のうち`cloudflare-ech.com`は8件＝0.002%）。**まれであっても、書いておかないと「その名前が行き先だ」と読まれます。**

## 脅威の照合はMac上で行われます

エージェントは「このアドレスは悪性か」と誰かに尋ねません。公開されている指標リストをダウンロード（またはHubから受領）し、**ローカルで比較します**。**あなたが通信した相手のアドレスは、脅威インテリジェンス提供者へ送られません。** 守るために、守るべき対象そのものを第三者に渡すことになるからです。

## 地球儀上の位置

地球儀は、既に観測済みの宛先を配置します。その照会は位置情報サービスではなく**あなた自身のHub**の `api/agent/geo-cache` へ行き、結果はキャッシュされます。Hubに登録していない場合、地球儀は配置するものが無く、その旨を表示します。

## 要理由APIの宣言

Appleは、フィンガープリンティングに使われてきた一部のAPIについて理由の宣言を求めています。エージェントが宣言しているのは2カテゴリで、実際の用途は以下のとおりです。

| カテゴリ | 理由コード | エージェントが実際に行っていること |
|---|---|---|
| User defaults | `CA92.1` | 自分の設定（ウィンドウ状態、再描画レート、言語）の読み書き |
| User defaults | `1C8F.1` | 双方が属するapp groupを通じたシステム拡張との設定共有 |
| File timestamp | `C617.1` | **自分で書いたファイルのサイズ**の読み取り。app groupコンテナ内の観測journalとstore、およびアプリの一時ディレクトリ内のダウンロード済み更新パッケージ |

ディスク容量・システム起動時刻・有効なキーボードの各カテゴリは使用していません。**これらへの呼び出しが宣言なしにソースへ現れた場合、リポジトリのテストが失敗します。** この表が黙って古くなることはありません。

## 自分で確認できること

上記はすべて、このページを信用せずに観測できます。

```bash
plutil -p "/Applications/EgressView Agent.app/Contents/Resources/PrivacyInfo.xcprivacy"
```

```bash
spctl -a -vvv -t install "/Applications/EgressView Agent.app"
```

```bash
codesign --verify --deep --strict --verbose=2 "/Applications/EgressView Agent.app"
```

そして相応しいことに、**EgressViewをエージェントが動いているMacに向けて、エージェント自身が何に接続しているかを見ることができます。**
