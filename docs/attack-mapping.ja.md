# EgressViewで分かること・分からないこと（MITRE ATT&CKとの対応）

[English](attack-mapping.md)

[MITRE ATT&CK](https://attack.mitre.org/)を使っている人向けに、今の版のEgressViewが示せる兆候と、それぞれに関係する技法、見逃す場合をまとめました。通信がどこへ行くかを見たいだけなら、このページではなく[概要](../README.ja.md)から読んでください。

EgressViewはマルウェアかどうかを判定しませんし、通信を止めることもしません。見ているのは接続のメタデータだけで、パケットの中身は読まないので、何が送られたか、攻撃が成功したかは分かりません。バックアップやクラウド同期、更新も、下の兆候のいくつかと同じ形になります。ここに技法が載っていても、その技法のすべての使われ方を見つけられるわけではありません。MITREの評価も受けていません。DLP・EDR・ファイアウォールの代わりにはなりません。

## リストにある悪性の宛先への接続

関係する技法: [T1071 Application Layer Protocol](https://attack.mitre.org/techniques/T1071/)（既知の指令サーバー）、[T1105 Ingress Tool Transfer](https://attack.mitre.org/techniques/T1105/)（既知のマルウェア配布元）

- 条件: 宛先のアドレスかホスト名が、abuse.chのFeodo Tracker・URLhaus・ThreatFox、またはSpamhaus DROPに載っている。HubとMac・WindowsのAgentが照合し、通知します。
- 確かめたこと: 自動テスト（`test/unit/threat-intel.test.js`、Macの`ThreatMatcherTests`）。開発者のネットワークで運用しています。
- 見逃すもの: まだリストに載っていない宛先。リリースの配布元のような共有サービスでの一致は、確度「低」として出します。

## ビーコン候補

関係する技法: [T1071 Application Layer Protocol](https://attack.mitre.org/techniques/T1071/)（指令サーバーへの定期的な問い合わせ）

- 条件: 送り元・宛先・ポート・プロトコルが同じ接続が4回以上あり、間隔の中央値が1分〜4時間で、変動係数が0.5以下。ルーターのデータだけから計算します。Hubの画面に候補として並べるだけで、通知はしません。
- 確かめたこと: 自動テスト（`test/unit/beacon-detector.test.js`）
- 見逃すもの: 間隔をわざとばらつかせた問い合わせ、1分より短い・4時間より長い間隔、ルーターを通らない通信。普通のアプリも決まった間隔で問い合わせるので、候補に出ても多くは正常です。

## 通常と異なる外向き通信

関係する技法: [T1041 Exfiltration Over C2 Channel](https://attack.mitre.org/techniques/T1041/)のうち、大量に送る部分

- 条件: 終わった15分間の送信量が、100 MiB、このコンピューターの中央値の3倍、中央値＋max(16 MiB, 6×MAD)のどれよりも多い。履歴が24時間分たまるまでは判定しません。送受信量の取れた接続が80%未満の15分間も使いません。超えたら通知します。
- 確かめたこと: 自動テスト（Macの`OutboundAnomalyDetectorTests`）。2026年9月に、普段使いのMacで実際に検知し、通知が出ました。
- 見逃すもの: 閾値より少ない送信、何回もの15分間に分けた送信、送受信量の取れない通信（[見えないもの](#見えないもの)を参照）

## 調べる候補（直近14日）

関係する技法（調べる手がかりとして）: [T1567 Exfiltration Over Web Service](https://attack.mitre.org/techniques/T1567/)、[T1030 Data Transfer Size Limits](https://attack.mitre.org/techniques/T1030/)

- 条件: 監視時間が168時間を超えた後で、次のどれかに当てはまったとき。
  - 初めて見るアプリと宛先の組が、最初の7日間に1 MiB以上送った
  - 前から知っている組が、1日に10 MiB以上、かつ普段の90パーセンタイルの5倍以上送った
  - コンピューター全体の24時間の送信量が、普段の99パーセンタイルの1.5倍を超えた
- 出る場所: Agentの「インサイト」タブ（Mac 0.5.139以降、Windows 0.1.165以降）。通知はせず、Hubにも送りません。
- 確かめたこと: 両方のAgentが、共通の試験データ`test/fixtures/outbound-candidates-cases.json`に合格。Mac 1台で、同じデータを再生した結果と画面の一覧が一致しました。実機でまだ見ていないのは、Macで候補が11件以上あるときと小さいウィンドウ、学習が終わったWindowsでの一覧です。
- 見逃すもの: 週1 MiB未満の新しい組、1日10 MiB未満の知っている組、ブラウザと仮想マシン（わざと除外）、LAN内の宛先、組ごとに下限を下回るよう分けた送信
- Mac 1台で9日間見たところ、1日に約1件出て、どれも持ち主が使っているアプリの送信でした。

## このコンピューターのプログラムによるLAN内の探索

関係する技法: [T1046 Network Service Discovery](https://attack.mitre.org/techniques/T1046/)、[T1018 Remote System Discovery](https://attack.mitre.org/techniques/T1018/)

- 条件: 1つのプログラムが2分以内に、LAN内の30個以上のアドレス、または1つのLAN内アドレスの10個以上のポートへ接続した。Agentから届いた記録をもとにHubが判定し、通知します。
- 確かめたこと: 自動テスト（`test/unit/lan-scan-detector.test.js`）。MacとWindows PCで、わざと掃引して通知まで届くことを確かめました。
- 見逃すもの: もっとゆっくりした探索、Agentの入っていない機器からの探索、プライベートアドレスの範囲外への探索

## LAN内の別の機器がこのコンピューターを探った

関係する技法: [T1046 Network Service Discovery](https://attack.mitre.org/techniques/T1046/)

- 条件: LAN内の1つの送り元が2分以内に、このコンピューターの10個以上のポートへ届いた。Hubが送り元を示して通知します。Macでは「パケットのヘッダーから数える」をオンにする必要があります（最初はオフ）。
- 確かめたこと: 自動テスト（Macの`InboundProbeTests`）。MacとWindows PCで、TCPとUDPの両方とも通知まで届くことを確かめました。
- 見逃すもの: もっとゆっくりした探り、数個のポートだけの探り、ヘッダーから数えていないMacへの探り

## Agentから届かない

関係する技法（考えられる原因の1つとして）: [T1562.001 Impair Defenses: Disable or Modify Tools](https://attack.mitre.org/techniques/T1562/001/)

- 条件: Agentから15分間何も届かず、その間にルーターがそのコンピューターの新しい接続を3件以上記録した。Hubが通知します。
- 確かめたこと: 自動テスト（`test/unit/agent-silence-detector.test.js`）。本番のデータで、スリープや電源オフでは出ないことを確かめました。本当に止まった場面を捉えたことはまだありません。
- 見逃すもの: ルーターの無いHubでは働きません。実際によくある原因は、更新や異常終了の後にアプリが起動し直さなかったことで、攻撃ではありません。

## 見えないもの

- Agentを入れていないコンピューターと、ルーターを通らない通信。LAN内の機器どうしの通信は、たいていルーターを通りません。ルーターからは、どのアプリが送ったかも分かりません。
- Macの多くの接続の送受信量。「パケットのヘッダーから数える」をオンにしない限り取れません。量で判定する兆候は、MacでもWindowsでもこうした通信を使いません。
- Agentが止まっている間、スリープ中、更新後にまだ起動していない間のこと。Agentは自分のコンピューターだけを見ます。
- AgentがHubへ送っていないときの、Hubが判定する兆候（LAN内の探索、探られた側、Agentから届かない）。Hubへ送るかは利用者が選びます。
- 送った中身。暗号化されているかどうかに関係なく、中身は読みません。
- 攻撃と、バックアップ・クラウド同期・大きなアップロード・更新・新しく入れたアプリとの違い
